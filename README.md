## Раздел 3. Управление файловыми системами

**3.1. Создание файловой системы.** К машине подключён второй диск `/dev/sdb`
объёмом 2 ГБ. На нём создана таблица разделов GPT и один раздел на всё
пространство, отформатированный в ext4 с меткой тома `MEPHI_WEB`.

```
parted -s /dev/sdb mklabel gpt
parted -s /dev/sdb mkpart primary ext4 1MiB 100%
mkfs.ext4 -L MEPHI_WEB /dev/sdb1
blkid /dev/sdb1
```

**3.2. Монтирование.** Создана точка монтирования `/mephi-web`, автоматическое
монтирование настроено в `/etc/fstab` **по метке тома**, как требует задание:

```
mkdir -p /mephi-web
echo 'LABEL=MEPHI_WEB  /mephi-web  ext4  defaults  0 2' >> /etc/fstab
mount -a
findmnt /mephi-web
```

Монтирование по метке, а не по имени устройства, устойчиво к изменению порядка
дисков: при добавлении ещё одного накопителя `/dev/sdb` может стать `/dev/sdc`,
а метка останется прежней.

Подтверждение: `fstab`.

## Раздел 4. Управление сервисами

**4.1. Веб-сервер**

```
systemctl enable --now nginx
systemctl is-enabled nginx   # enabled
systemctl is-active nginx    # active
```

Команда `enable --now` одновременно запускает службу и включает её автозапуск

**4.2. Журналирование**


Ключ `-u` ограничивает выборку одной службой, `-b` — текущей загрузкой системы.

Подтверждение: `journalctl.out`.

## Раздел 5. Управление доступом

### 5.1. Дискреционное управление доступом (DAC)

Созданы три разработчика с заданными идентификаторами и два куратора в группе
с заданным GID:

```
groupadd -g 5500 developers
useradd -u 5501 -g developers -m user1
useradd -u 5502 -g developers -m user2
useradd -u 5503 -g developers -m user3
groupadd -g 4444 curators
useradd -g curators -m curator1
useradd -g curators -m curator2
```

Каталог проекта и права на него:

```
mkdir -p /data/mephi-2026
chown root:developers /data/mephi-2026
chmod 2770 /data/mephi-2026
setfacl -m g:developers:rwx,g:curators:r-x,o::--- /data/mephi-2026
setfacl -d -m g:developers:rwx,g:curators:r-x,o::--- /data/mephi-2026
```

Пояснение к решению. Обычных прав доступа для выполнения требования
недостаточно, поэтому задействованы два механизма.

Ведущая цифра `2` в режиме `2770` — это **бит set-GID на каталоге**. Он
заставляет каждый создаваемый внутри файл наследовать группу каталога, то есть
`developers`. Без него файл получал бы основную группу своего создателя, и
остальные участники команды доступа к нему не имели бы.

Ключ `-d` во второй команде `setfacl` задаёт **ACL по умолчанию**. Именно он
закрывает требование «на ВСЕ файлы, которые будут создаваться ЛЮБЫМ из
участников»: каждый новый объект внутри каталога автоматически получает права
`rwx` для группы `developers` и `r-x` для группы `curators`. Запись `o::---`
закрывает доступ всем остальным.

**Проверка выполнена на практике:**

```
sudo -u user1 touch /data/mephi-2026/test.txt        # файл создан, группа developers
sudo -u user2 bash -c 'echo ... >> .../test.txt'      # запись в чужой файл — успешно
sudo -u curator1 cat /data/mephi-2026/test.txt        # чтение — успешно
sudo -u curator1 bash -c 'echo ... >> .../test.txt'   # запись — Отказано в доступе
```

Подтверждение: `stat.out`, `passwd`, `group`.

### 5.2. Привилегии (уменьшение количества set-UID-программ)

Вместо бита set-UID, дающего программе все права root, утилите `tcpdump` выданы
две точечные возможности:

```
chmod u-s /usr/sbin/tcpdump
setcap cap_net_raw,cap_net_admin=eip /usr/sbin/tcpdump
getcap /usr/sbin/tcpdump > ~/getcap.out
```

`CAP_NET_RAW` разрешает открывать «сырые» сокеты, то есть собственно
перехватывать пакеты; `CAP_NET_ADMIN` нужен для перевода интерфейса в
неразборчивый режим. Всё остальное, что умеет root, утилите недоступно — в этом
и состоит смысл замены set-UID на привилегии.

**Проверка от имени обычного пользователя:**

```
sudo -u user1 /usr/sbin/tcpdump -c 1 -i any
```

Перехват выполнен успешно: `1 packet captured`.

Подтверждение: `getcap.out`.

### 5.3. Мандатное управление доступом (MAC)

SELinux работает в режиме `Enforcing` — проверено командой `getenforce`.

Веб-сервер переведён на нестандартный каталог `/mephi-web`:

```
sed -i '41s|/usr/share/nginx/html|/mephi-web|' /etc/nginx/nginx.conf
nginx -t
systemctl restart nginx
```

Одной лишь правки конфигурации недостаточно: файлы в новом каталоге имеют тип
`unlabeled_t`, и SELinux запретил бы веб-серверу их читать. Поэтому задан
постоянный контекст:

```
semanage fcontext -a -t httpd_sys_content_t "/mephi-web(/.*)?"
restorecon -Rv /mephi-web
```

Команды выполняют разные задачи и нужны обе. `semanage fcontext` записывает
правило в политику SELinux — «файлам по этому пути полагается такой тип», — и
это правило сохраняется после перезагрузки. `restorecon` применяет правило к уже
существующим файлам немедленно. Вывод `restorecon` зафиксировал смену типа с
`unlabeled_t` на `httpd_sys_content_t`.

Подтверждение: `getenforce.out`, `stat.out` (вторая запись содержит контекст
каталога `/mephi-web`).

## Раздел 6. Аутентификация

### 6.1. Ограничение входа для пользователей

Кураторам запрещён вход с локальной консоли при сохранении доступа для всех
остальных пользователей. Задача решена PAM-модулем `pam_access`:

```
echo '-:curators:LOCAL' >> /etc/security/access.conf
echo 'account    required     pam_access.so' >> /etc/pam.d/login
```

Строка в `access.conf` читается так: `-` — запретить, `curators` — кому,
`LOCAL` — откуда. Правка внесена именно в `/etc/pam.d/login`, а не в
`/etc/pam.d/sshd`, поскольку задание требует запретить вход **локально, через
консоль**; удалённый доступ кураторам остаётся.

Решение через `usermod -s /sbin/nologin` сознательно отвергнуто: оно запрещает
вход вообще отовсюду и потому не соответствует условию.

### 6.2. Управление паролями

```
sed -i 's/^#\?\s*minlen.*/minlen = 12/' /etc/security/pwquality.conf
sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS\t90/' /etc/login.defs
for u in user1 user2 user3 curator1 curator2; do chage -M 90 $u; done
chage -l user1
```

Срок действия пароля задан дважды намеренно: правка `login.defs` распространяет
правило на учётные записи, которые будут созданы в будущем, а `chage` применяет
его к уже существующим. Пароли заданы после настройки политики, поэтому
соответствуют требованию минимальной длины в 12 символов.

Результат `chage -l user1`: максимальное количество дней между сменой пароля —
90, срок действия текущего пароля истекает 27 января 2027 года.

Подтверждение: `shadow`, `pwquality.conf`.

## Сохранность настроек после перезагрузки

Все выполненные настройки сохраняются после перезагрузки системы, поскольку
записаны в постоянные хранилища, а не в оперативные параметры:

- имя хоста — в `/etc/hostname`;
- монтирование — в `/etc/fstab`;
- автозапуск nginx — символьной ссылкой в `multi-user.target.wants`;
- учётные записи, группы и сроки действия паролей — в `/etc/passwd`,
  `/etc/group`, `/etc/shadow`;
- права и ACL каталога проекта — в метаданных файловой системы;
- привилегии `tcpdump` — в расширенном атрибуте `security.capability`;
- контекст SELinux для `/mephi-web` — правилом в политике через
  `semanage fcontext`;
- политика паролей и правила PAM — в `/etc/login.defs`,
  `/etc/security/pwquality.conf`, `/etc/security/access.conf`,
  `/etc/pam.d/login`.
